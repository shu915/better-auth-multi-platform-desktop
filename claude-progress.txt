## 決めたこと
- 配布は自分の Mac だけ(公証なし)。識別子 com.shu915.authpractice.desktop、アプリ名 Auth Practice
- 秘密は Rust と Keychain だけ。JS には、Keychain を触るコマンドも、deep link の権限も渡さない。JS の権限は event の購読(listen、unlisten)だけ
- Web の口は /api/mobile/* をそのまま使う(名前の一般化は、後で考える)
- Web の URL は AUTH_WEB_URL、Go の URL は AUTH_API_URL で、ビルド時に埋め込む。デバッグの既定は http://localhost:3000 と http://localhost:8080、リリースは https 必須

## .app を試すとき(deep link は、ビルドした .app を /Applications に入れたときだけ届く)
- ビルド(署名付き。人が自分のターミナルで)と入れ替えの手順は、README と CLAUDE.md の「署名」。入れ替えは ditto を使う(署名を保つため)。target/ 側の .app も登録されるので、lsregister -u で外す。メールのリンクが古い .app に渡ると、古い画面が出る
- ログを見る: "/Applications/Auth Practice.app/Contents/MacOS/tauri-app" をターミナルから起動(デバッグビルドは [auth] … を出す。秘密は出さない)。リリースビルドは何も出さない
- 署名付きなら、ビルドし直しても Keychain の許可は聞かれない。署名なし(tauri dev など)は、ビルドのたびに聞かれる。ログインと退会の確認は、署名付きの .app で

## 既知の限界・注意
- 引き換えが失敗すると、そのリンクは使い切りで、再試行できない(もう一度リンクを頼む。設計どおり)
- 攻撃者のプロセスが同じ Mac で受け口のポートを待ち受け、攻撃者の cc を付けたログインメールを開かせると、コードを受けられる(独自スキームと同じ限界。Web の docs/design.md)
- Cargo.lock で rust-ini を 0.21.1 に固定している。0.21.3 は tauri-plugin-deep-link 2.6.2 の Linux 用のコードをコンパイルできなくし、CI(Ubuntu)が落ちる(Mac では気づかない)。deep-link の新しい版が出たら、固定を外せるか試す(cargo update -p rust-ini で CI が通るか)
- Dependabot の glib(Linux 用、Tauri が固定)は、更新できないと失敗扱いになる。Mac には関係ない
- 署名の証明書(無料の Apple Development)は、2027 年 10 月 27 日に切れる。更新したら、Keychain の許可を、もう一度聞かれることがある
- Render の DB は 2026-11-08 に期限が切れる
