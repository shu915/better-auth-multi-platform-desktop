## 決めたこと
- 範囲: メールのログイン、プロフィール、退会 → 動いたら Google
- 配布は自分の Mac だけ(公証なし)
- 識別子 com.shu915.authpractice.desktop、アプリ名 Auth Practice
- Web の口は /api/mobile/* をそのまま使う(名前の一般化は、後で考える)
- 秘密は Rust と Keychain だけ。JS には、Keychain を触るコマンドも、deep link の権限も渡さない。JS の権限は event の購読(listen、unlisten)だけ
- Web の URL は、ビルド時に AUTH_WEB_URL で埋め込む。デバッグは http://localhost:3000、リリースは https 必須

## .app を試すとき(deep link は、ビルドした .app を /Applications に入れたときだけ届く)
- ビルド: npm run tauri build -- --debug --bundles app(デバッグビルドは localhost に繋げる。リリースは https 必須)
- 入れ替え: rm -rf "/Applications/Auth Practice.app" && cp -R src-tauri/target/debug/bundle/macos/"Auth Practice.app" /Applications/
- ログを見る: "/Applications/Auth Practice.app/Contents/MacOS/tauri-app" をターミナルから起動(デバッグビルドは [auth] link outcome: … を出す。秘密は出さない)
- 偽リンクを試す: open -g "betterauthmulti:///?state=zzz&code=$(date +%s)"(code は毎回変える。同じ code は 2 回目から無視される。-g がないと open が前に出す)
- ビルドし直すと、Keychain の許可を聞かれる(署名がないため)。「常に許可」を選ぶ

## 既知の注意
- Web の /api/auth/expo-authorization-proxy の open redirect(モバイルと共通の未対応)
- 引き換えが失敗すると、そのリンクは使い切りで、再試行できない(もう一度リンクを頼む。設計どおり)

- Dependabot の glib(Linux 用、Tauri が固定)は、更新できないと失敗扱いになる。Mac には関係ない
- 残りのリモートブランチの削除(あとでまとめて)
